SECTION 1: TWO AVATAR SYSTEMS IDENTIFIED
================================================================================

SYSTEM A: USER AVATARS (Per-User Profile Pictures)
---------------------------------------------------
Location: Qiniu Cloud OSS
Path: /blog/image/userAvatar/{userId}.png
Management: Admin Interface → User List Page
Upload Method: Direct file upload with admin authentication
Database: Stored as references in user table (implicit)
Display: Comments, messages, user profiles
File Format: PNG (converted on upload)
Max Size: 30MB
Rate Limit: 5 uploads per period per user


SYSTEM B: AUTHOR/SITE AVATAR ("my-avatar" Configuration)
---------------------------------------------------------
Location: MySQL database configuration table
Table: configuration
Field: label="my-avatar", content="{URL}", type="STRING"
Management: Admin Interface → Configuration Page
Update Method: URL text entry in configuration editor
Database: Explicit entry in configuration table
Display: Home page, About page, Author profile in comments/messages
File Format: Any format (URL-based)
Max Size: No size limit (stored as URL only)
Rate Limit: None (configuration update only)

SECTION 3: COMPLETE REQUEST FLOWS
================================================================================

FLOW A: Upload User Avatar (Admin)
==================================
1. Admin clicks "编辑" on user row
2. Avatar upload field appears
3. Admin selects image file
4. POST /api/oss/uploadImageQueryIn?path=/image/userAvatar/{userId}
   - Content-Type: multipart/form-data
   - Authorization: Bearer {admin-token}
   - Body: {file: binary data}
5. Backend:
   a) Validates token via checkPermissions()
   b) Reads file from request (formidable)
   c) Saves to temp: /temp/images/{random}
   d) Uploads to Qiniu: /blog/image/userAvatar/{userId}.png
   e) Deletes temp file
   f) Returns response: {code: 200, url, path, name}
6. Frontend:
   a) Shows success notification
   b) Displays image from: VUE_APP_OSS_IMAGE_BASE_URL + /blog/image/userAvatar/{userId}.png
   c) Image shown at 100px width in table


FLOW B: Update Author Avatar ("my-avatar")
===========================================
1. Admin navigates to Configuration page
2. Admin searches for "my-avatar"
3. Admin clicks Edit button
4. Text field appears with current URL
5. Admin updates URL and clicks Save
6. POST /api/configuration/updateConfiguration
   - Authorization: Bearer {admin-token}
   - Body: {id, label: "my-avatar", content: "new-url", type: "STRING"}
7. Backend:
   a) Validates token via checkPermissions()
   b) Updates configuration table row
   c) Returns: {code: 0, message: "更新成功"}
8. Frontend:
   a) Frontend fetches: GET /api/configuration/reception/getConfig
   b) Response: {my-avatar: {id, label, content, type}}
   c) Stores in Pinia/Vuex: store.$state.config['my-avatar']
   d) All pages reactively update to show new URL


FLOW C: Display Avatar on Frontend
==================================
1. Page component mounts
2. Checks store for config: store.$state.config['my-avatar']?.content
3. If author post/comment:
   - Uses: store.$state.config['my-avatar']?.content
4. If user post/comment:
   - Uses: config.public.ossUrl + /image/userAvatar/{userId}.png
   - May include ?timestamp={date} for cache busting
5. Avatar displayed with fallback if unavailable
6. For user avatars: NaviHeader component shows logged-in user's avatar

SECTION 5: API ENDPOINTS SUMMARY
================================================================================

AUTHENTICATION: All admin endpoints require Bearer token (JWT)

USER AVATAR ENDPOINTS:
  POST /api/oss/uploadImageQueryIn?path=/image/userAvatar/{userId}
    - Admin-only
    - Upload user avatar to Qiniu Cloud
    - Response: {url, path, name}

CONFIGURATION ENDPOINTS:
  GET /api/configuration/getAllConfiguration
    - Admin-only
    - Get all configuration entries
    - Response: [{id, label, content, type}...]
    
  GET /api/configuration/reception/getConfig
    - Public (no auth required)
    - Get all configurations (frontend access)
    - Response: {config-label: {id, label, content, type}...}
    
  POST /api/configuration/addConfiguration
    - Admin-only
    - Create new configuration
    - Body: {label, content, type}
    - Response: {id, label, content, type}
    
  POST /api/configuration/updateConfiguration
    - Admin-only
    - Update configuration entry
    - Body: {id, label, content, type}
    - Response: success message
    
  DELETE /api/configuration/deleteConfiguration?id={id}
    - Admin-only
    - Delete configuration entry
    - Response: success message

TABLE: user
  - id (BIGINT, PRIMARY KEY, AUTO_INCREMENT)
  - name (VARCHAR 255, NOT NULL)
  - mail (VARCHAR 255, NOT NULL, UNIQUE)

  - id (INT, PRIMARY KEY, AUTO_INCREMENT)
  - label (VARCHAR 255, NOT NULL)
  - content (JSON, NOT NULL)
  - type (VARCHAR 150, NOT NULL)
  
  Key Entry for Avatar:
    - label: "my-avatar"
    - content: "https://example.com/avatar.png" (or similar URL)
    - type: "STRING"

================================================================================

SECTION 10: KEY INSIGHTS & TAKEAWAYS
================================================================================

1. DUAL AVATAR SYSTEM
   - User avatars: File-based (Qiniu Cloud OSS)
   - Author avatar: Configuration-based (MySQL URL)
   - Different management interfaces and workflows

2. ARCHITECTURE PATTERN
   - Backend: Express.js + Sequelize (ORM)
   - Admin UI: Vue 3 with Ant Design Vue
   - Frontend: Nuxt 3 SSR with state management
   - Storage: Qiniu Cloud OSS (external)

3. AVATAR DISCOVERY LOGIC
   - Frontend checks: if userId == -1 → use my-avatar config
   - Otherwise → use /image/userAvatar/{userId}.png

4. CACHE MANAGEMENT
   - Avatar timestamp param: ?timestamp={date}
   - Prevents browser cache from showing old avatars
   - Regenerated on avatar update

5. ADMIN WORKFLOW
   - Two separate panels: User List + Configuration
   - User avatars: Inline upload in table
   - Site avatar: Configuration text editor

6. SECURITY MODEL
   - Rate limiting on uploads
   - Token-based authentication
   - Path validation for uploads
   - File type whitelist
