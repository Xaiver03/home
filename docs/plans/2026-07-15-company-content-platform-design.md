# 晓黎团队内容平台设计

## 目标与边界

晓黎团队官网继续以 AI 技术产品团队为主叙事，同时拥有独立的公司介绍、博客、文章归档、分类、留言和友链。现有 `blog-frontend`、`blog-admin`、`blog-api` 作为内容平台代码复用，不复制第二套实现。CEO 个人站不进入公司内容流，只作为友链展示。本次只改本地代码、开发数据库和示例配置，不连接、迁移或写入服务器生产数据库。

客户案例仍不加入官网，也不作为本轮内容平台的初始数据。

## 运行与数据隔离

同一套博客代码以“单站点、独立运行实例”服务晓黎团队。开发环境默认使用新的 `apps/blog-api/database.company.dev.db`，不再读取原来的个人开发库；生产环境继续通过环境变量选择 MySQL，但公司部署必须使用独立数据库名、独立存储前缀和独立站点 URL。代码不做表级多租户，也不向现有表增加 `siteId`，从而避免生产迁移风险。

新增公司内容初始化脚本，职责只有两项：创建当前模型所需表结构；对缺失的公司配置和 CEO 友链执行幂等 `findOrCreate`。脚本不得覆盖已经由后台编辑过的内容。公司默认配置包含品牌名称、Logo、文章署名、About 文案和社交链接。

## 信息架构与导航

公开路由保持现有兼容性：`/` 为公司官网，`/blog/` 为公司博客，`/blog/log/article` 为文章归档，`/blog/log/category` 为分类，`/blog/about` 为完整公司介绍，`/blog/link` 为友链，`/blog/message` 为留言。

官网和博客统一使用原博客的悬浮玻璃胶囊导航语言：品牌区、胶囊式入口切换、清晰激活态、主题/菜单工具区；移动端使用紧凑顶栏与底部主标签。两个应用不强行共享框架耦合的 Vue 组件，而是共享导航内容模型与设计 token，分别实现轻量组件。导航项目统一为“官网、博客、文章、关于我们、友链、合作”。

## 内容数据流与降级

首页只从公司 API 读取最新公开文章和站点联系配置。成功时展示公司文章预览；公司数据库为空或 API 不可用时显示明确的“内容筹备中”状态，邮件合作入口保持可用，不回退到个人内容。博客前端所有 SEO、作者、头像、About 和页脚信息优先读取公司配置，并提供晓黎团队默认值，禁止出现个人站硬编码。

友链由现有后台管理。CEO 个人站以普通已通过友链初始化，后续可在后台修改。文章、分类、留言、登录和管理流程继续使用现有 API，不改变数据模型和权限边界。

## 验证

新增测试覆盖公司数据库路径、幂等默认配置、CEO 友链、公司导航模型和个人文案禁入规则。首页、博客前端和 API 分别运行测试；首页与博客前端运行生产构建；博客 API 运行完整 Jest；管理后台运行生产构建。最终做源码扫描、构建产物扫描与 `git diff --check`，确认没有生产数据库文件、密钥或构建产物进入提交。
